## 완료 — 애드센스 계정 연동

- **계정 확인 정보 삽입 완료.** 게시자 ID `ca-pub-8650152036785492`의
  `google-adsense-account` 메타 태그를 모든 공개 HTML 페이지에 넣었다.
- **광고 로더 범위 조정 완료.** `adsbygoogle.js`는 독립적으로 읽을 수 있는 계약 유형별
  가이드 페이지에만 넣었다. 점검 도구, 소개, 개인정보처리방침, 이용약관, 판정 기준 페이지에는
  광고 로더를 두지 않는다.
- **[ads.txt](../ads.txt) 추가 완료.** `google.com, pub-8650152036785492, DIRECT, f08c47fec0942fa0`.
  게시자 ID가 바뀌면 이 파일도 함께 갱신해야 한다.

## 아직 남은 것

1. **실제 광고 단위(ad unit) 배치** — 지금 넣은 스크립트는 애드센스 계정과 사이트를
   연결하는 로더일 뿐, 화면에 광고가 보이지는 않는다. 애드센스 대시보드에서 심사가
   통과되면 자동 광고를 켜거나, 광고 단위 코드를 받아 원하는 위치(`<ins class="adsbygoogle">`)에
   넣어야 실제 광고가 노출된다.
2. **광고 배치 시 UX 확인** — 계약서 점검처럼 사용자가 실수하면 안 되는 흐름(업로드 버튼,
   문의 제출 버튼) 근처에는 광고를 붙이지 말 것. 애드센스 정책상 클릭 유도 배치는 계정
   정지 사유가 된다.

## 검토는 했지만 지금은 손대지 않은 것

- **EU 방문자 동의 배너(CMP)** — 구글은 EEA·영국·스위스 방문자에게 광고를 보여주려면
  구글이 인증한 동의관리플랫폼(CMP)을 통해 동의를 받도록 요구한다(Google EU 최종
  사용자 동의 정책). 이 사이트는 한국어 전용이라 EU 트래픽 비중이 낮을 것으로 보이지만,
  0은 아니다. 애드센스 승인 후 계정의 "개인 정보 보호 및 메시지" 설정에서 구글이 제공하는
  기본 CMP를 켜는 것으로 충분한 경우가 많다 — 별도 코드 작업이 필요 없을 수 있으니
  애드센스 대시보드에서 먼저 확인할 것.
- **도메인** — 지금은 `contract-check-one.vercel.app` 서브도메인이다. 커스텀 도메인은
  신뢰도·브랜딩 면에서 유리할 수 있지만 콘텐츠 품질 문제를 대신 해결하지는 않는다.
  도메인을 바꾸면 `sitemap.xml`, `robots.txt`, 모든 페이지의 `canonical`·OG URL을
  전부 새 도메인으로 갱신해야 한다 (문자열 `contract-check-one.vercel.app`로 검색하면
  전부 찾을 수 있다).
- **콘텐츠 품질** — Google이 공개한 최소 페이지 수나 최소 글자 수 기준은 없다.
  새 가이드는 숫자를 채우기 위한 글이 아니라 실제 계약 검토 순서, 예시, 자동 판정 한계와
  공식 자료를 함께 제공하도록 유지한다. 출처와 시행일은 재심사 전 다시 점검할 것.
